## يحتاج API (أولوية عالية)

### فلاتر لا تغيّر البيانات

- `days`, `governorateId`, `granularity` على: العرض مقابل الطلب، تغير السعر، نشاط المستخدمين، المنتجات الأكثر طلباً، توزيع التغليف، إجمالي المعروض، إلخ.
- عند اختيار محافظة في «أقل إنتاجاً» / «قليلة التوفر»: ترتيب **داخل المحافظة فقط** وليس على مستوى سوريا.

### بيانات ناقصة / منطق

| التقرير / الموضوع | المطلوب |
|-------------------|---------|
| المساحات الزراعية | `areaHectares` من تسجيل المزارع |
| الحسابات النشطة داخل المحافظة | KPI مزارع/تاجر/ناقل غير صفر |
| الشكاوى (إرشاد، نقل، تجارة) | استعلامات + `nameAr` للأنواع |
| متوسط زمن النقل | `deliveredAt - pickedUpAt` من أزرار الناقل |
| إجمالي المعاملات (تجارة) | مجموع كلي ≠ مجموع كل محافظة |
| الأسعار الحكومية vs التنفيذ | إرجاع بيانات أو رسالة «لا بيانات» |
| منتجات قليلة التوفر | بيانات لكل جهة |
| محافظة/منطقة «غير محدد» | JOIN على `GovernorateId` / `AreaId` |

### خرائط API

- `GET /api/gov/maps/farms` — إحداثيات داخل سوريا
- `GET /api/gov/maps/products` — توزيع محافظات صحيح
- خريطة الإنتاج في التحليلات: `visualizationType: map` + `points[]`

### catalog

يُفضّل أن يُرجع كل عنصر في `/api/gov/analytics/catalog` حقل **`supportedFilters`** دقيقاً، مثلاً:

```json
"supportedFilters": ["days", "governorateId", "categoryId", "productId", "granularity"]
```

## التحقق بعد النشر

1. `npm run build` ثم نشر `dist` أو `pm2` + `ecosystem.config.cjs`.
2. افتح تحليل **المنتجات الأكثر طلباً** → غيّر الفترة → Network: `?days=7` ثم `?days=30`.
3. اختر محافظة → يجب `governorateId=N` في URL الطلب.
4. تقرير **الكمية بين المحافظات** → يجب ظهور فلتري المصدر والوجهة.
5. رسم **تغير السعر** → تمرير أفقي داخل البطاقة عند فترة سنة.
6. دائري → أسماء منتجات وليس `#1`.

إن تغيّر `appliedFilters` في JSON ولا تتغير الأرقام → **تذكرة API**.
